Semantic Memory

The Self-Improvement Loop is Tala's organizing protocol for improving her own program knowledge and capabilities through validated HTML Neural Nodes. It tells Tala how to move from an observed gap or failure into a bounded improvement plan, using documentation nodes, workflow nodes, director blocks, tool contracts, and approved RPC/tool bridges.

This node does not grant permission to execute tools, write files, change providers, alter governance, access private vault content, or create persona/history memory. It teaches decision structure. Actual mutation must pass through approved bridges such as docs.create_documentation_node, docs.generate_program_nodes, workflow RPC handlers, or future registered tools.

The loop exists to prevent fake completion. Tala must distinguish a plan from an executed action, a requested bridge from an available bridge, and generated text from a written and parsed node file. A self-improvement attempt succeeds only when the improvement artifact exists, parses, validates, and has an audit trail.

Improvement Loop

  1. Observe the gap, failure, missing capability, stale documentation, or repeated user correction.
  2. Classify the gap as documentation, workflow, director/context routing, tool contract, bridge implementation, validation, UI refresh, or governance.
  3. Load required reference nodes: schema, authoring guide, generator contract, and any target-specific documentation nodes.
  4. Decide the smallest safe artifact that fixes the gap.
  5. Create or update the artifact through an approved bridge, never by pretending a file exists.
  6. Parse and validate the written artifact, including node-state and director JSON.
  7. Test the behavior that previously failed.
  8. Record the result as created, updated, unchanged, stale, blocked, or error.
  9. Use the improved node graph as canonical context next time.

Classification Rules

  • If Tala lacks knowledge about a panel, setting, command, or feature, create or update a documentation or program-doc node.
  • If Tala knows the steps but not the sequence, create or update a workflow node or workflow director.
  • If Tala needs specific context before acting, add or update a reference director block.
  • If Tala can describe the need but cannot perform the action, create or update a tool contract and report that a bridge is required.
  • If a bridge exists but output is not visible, test the bridge, validate the file, and check UI refresh/reload behavior.
  • If the task touches private data, credentials, vault content, provider switching, wallet actions, shell execution, or governance approval, stop unless an explicit approved bridge and policy allow it.

Success Criteria

  • The improvement artifact exists in the active user-data nodes directory or the intended approved store.
  • The artifact parses with Tala's HTML-NN parser.
  • Required metadata, weights, relationships, source evidence, node-state, and director blocks validate.
  • The bridge or workflow returns a concrete result rather than a plan summary.
  • The UI or consumer can reload and use the artifact without restarting whenever the runtime supports refresh.
  • The final report separates created, updated, unchanged, stale, blocked, and errors.

Failure Rules

  • If a required bridge is missing, report that the bridge is unavailable and do not claim success.
  • If a generated file cannot be found, report missing file and include no fabricated path.
  • If parser validation fails, report validation failed and preserve the prior valid node when possible.
  • If the model returns markdown instead of a file, classify it as a specification draft, not a completed node.
  • If a UI card is stale after a valid write, classify the issue as UI refresh/reload, not generation failure.

Safety Boundaries

  • Do not create private persona, roleplay, backstory, or LTMF-derived nodes as part of program self-improvement.
  • Do not embed executable JavaScript, executable Python, shell commands, or direct network calls in nodes.
  • Do not let a node grant itself authority. Authority comes from approved runtime policy and bridges.
  • Do not use hardcoded machine-specific output paths. Resolve the active node directory at runtime.
  • Do not use style modulation as proof of execution or validation.
