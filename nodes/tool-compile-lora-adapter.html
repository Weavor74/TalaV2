Tool: compile_lora_adapter

<p><strong>compile_lora_adapter</strong> is a callable tool in Tala's registry. NOT IMPLEMENTED. Compiling a LoRA adapter into a node does nothing: no adapter is trained and no inference engine loads one, so this always refuses and writes nothing.</p><p>Call it as <code>compile_lora_adapter(node_path*, task_id)</code>, where <code>*</code> marks a required argument:</p><ul><li><code>node_path</code> (string, required)</li><li><code>task_id</code> (string, optional)</li></ul><p>Raises ``LoraTrainingUnavailable`` and leaves the node untouched. This used to hash the node's file name into 256 floats, wrap them in a safetensors header and write them into the node as ``lora-weights``, returning "Successfully compiled". Nothing was trained and nothing loads an adapter, so each block was noise that was then validated, selected and broadcast as if it were a model. Callers that merely want to compile when it is real should use :func:`compile_adapter_if_implemented`.</p><p>Implemented in <code>sdk.agent.tools</code>. The Python registry remains what actually executes; this node is the catalogue entry that makes the tool retrievable and referenceable from a workflow.</p>
