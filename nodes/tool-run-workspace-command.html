Tool: run_workspace_command

<p><strong>run_workspace_command</strong> is a callable tool in Tala's registry. Run a shell command asynchronously in the workspace root. Pass timeout_seconds for anything long-running -- the default is only 30s, which is far too short for generation or test runs.</p><p>Call it as <code>run_workspace_command(command*, env, timeout_seconds)</code>, where <code>*</code> marks a required argument:</p><ul><li><code>command</code> (string, required)</li><li><code>env</code> (string, optional)</li><li><code>timeout_seconds</code> (string, optional)</li></ul><p>`timeout_seconds` defaults to 30, inherited from AsyncShellExecutor. That silently killed any genuinely long job: the training-story generator needs roughly 85 seconds *per story*, so a five-story run was cut off at 30s and reported as a failure with partial stdout, with nothing in the message explaining that a timeout was the cause. Callers running generation, migrations, or test suites must raise it.</p><p>Implemented in <code>sdk.agent.tools</code>. The Python registry remains what actually executes; this node is the catalogue entry that makes the tool retrievable and referenceable from a workflow.</p>
