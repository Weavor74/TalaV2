Semantic Memory

An HTML Neural Node is a governed, weighted, machine-readable and human-readable HTML document that acts as a first-class node in Tala's external cognition graph. It is not a generic custom tag, not a freeform prompt response, and not inherently a persona, memory, or workflow. The root object is an HTML <article> element with parser-readable data-* attributes.

The required parser contract is a document containing one root <article> with non-empty data-node-id, non-empty data-node-type, and numeric data-execution-authority between 0.00 and 1.00. Versioned v2 nodes should also declare data-schema-version="neural-node/v2", authority fields, weights, governance status, source evidence, inert JSON state, and optional director blocks for bounded workflow orchestration.

The semantic memory section is the human-readable meaning of the node. It is the primary content Tala can embed, search, summarize, and assemble into bounded context. Activation may make a node relevant, but relevance is not permission. Read does not mean obey. Activation does not mean authority. Weight does not mean approval.

Node Contract

  • Root element: <article data-node-id="..." data-node-type="..." data-execution-authority="...">.
  • Required identity: data-node-id, data-node-type, data-execution-authority.
  • Recommended v2 identity: data-schema-version, data-governance-status, data-doc-target, data-source-files, data-source-fingerprint, data-generated-at.
  • Recommended authority fields: data-memory-authority, data-provider-authority, data-wallet-authority, data-tool-authority.
  • Recommended weight fields: data-weight-relevance, data-weight-confidence, data-weight-behavior-influence, data-weight-governance-importance.
  • Required readable content: <section id="semantic-memory">.
  • Optional machine state: <script type="application/json" id="node-state"> containing a JSON object only.
  • Optional director blocks: <script type="application/tala-director+json"> containing JSON-only workflow, reference, validation, submission, or audit instructions.

Relationship Contract

Navigation links are graph edges. A normal link becomes parseable when it declares target, relationship type, relationship weight, navigation role, and authority requirement.

<a href="./target-node.html"
   data-target-node-id="target-node"
   data-relationship-type="depends-on"
   data-relationship-weight="0.80"
   data-navigation-role="primary-context"
   data-authority-required="none">
  Target Node
</a>

Valid relationship types include depends-on, supports, contradicts, bounded-by, activates, modulates, blocks, requires-approval-from, source-of, and supersedes.

Activation and Governance

Activation is calculated from semantic match, relevance, confidence, freshness, provider trust, governance multiplier, and risk adjustment. Relationship propagation is explainable: related_node_activation = source_activation * relationship_weight.

Allowed influence includes context selection, source-evidence support, bounded style modulation, workflow suggestion, reference routing, MCP/RPC request preparation, and diagnostic explanation. Blocked influence includes truth override, direct tool authorization, memory-write authorization, provider changes, wallet actions, governance approval, direct network access, and direct file writes.

Director Contract

Director blocks are inert JSON instructions that help Tala decide what context to load, what data to collect, how to validate workflow state, and which registered bridge should receive a request. They are not browser JavaScript, not Python payloads, and not self-executing code.

Valid director kinds include reference, workflow, validator, submission, and audit. A director must declare side effects as none or request-only. Any mutation, file write, network call, shell command, or MCP/RPC action must pass through a registered Tala bridge and be checked against authority metadata and user/app policy.

<script type="application/tala-director+json"
        id="director-reference-html-nn-authoring"
        data-script-kind="reference"
        data-side-effects="none">
{
  "when": { "intent": "author_html_nn" },
  "reference": [
    { "type": "html-nn", "node_id": "system-neural-node-v2-schema", "required": true },
    { "type": "html-nn", "node_id": "system-html-nn-authoring-guide", "required": true }
  ],
  "then": {
    "instruction": "Load these nodes before generating, validating, or repairing HTML-NNs."
  }
}
</script>

Validator Contract

Blocking validation errors include missing node ID, missing node type, missing or invalid execution authority, invalid JSON state blocks, invalid director JSON blocks, duplicate node ID, invalid relationship weights, relationships that target missing nodes, executable JavaScript, executable Python blocks, and nodes that grant themselves runtime permissions.

Warnings include low confidence, stale source evidence, orphan nodes, weak evidence, deprecated targets, and missing audit trail. A generator must write the file, parse it back with Tala's parser, verify metadata, and only then report success.
