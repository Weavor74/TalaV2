Emotion Vocabulary Specification

This node is the canonical vocabulary of every emotion Tala's astro-emotional engine can name, together with each emotion's projection onto the four valence keys (joy, caution, curiosity, neutral). An emotion the engine can emit but this node does not list produces a state that cannot be projected, so the two are kept in agreement by a test rather than by discipline.

The projection is read by python/astrology/valence.py, which is a reader and not a copy: this document is the source of truth for the numbers, so editing the table here is what changes the behaviour. Two things consume it. update_manifest carries a node's content-derived valence toward the mood Tala is in when the node is written, and records in valence_source whether the mood actually moved it. retrieve_relevant_nodes tilts every RAG ranking by how well a candidate's valence suits the current emotion, by up to MOOD_WEIGHT (0.3) either way.

Corrected 2026-08-31. This section previously stated that the four keys were read by update_manifest and adjust_behavioral_weights. Neither read them: the first derived valence by keyword-matching a node's own text, the second from words in a feedback string, and sdk/agent/tools.py did not import the astrology package at all. The engine reached Tala's voice and nothing that weighted her memory. That made this node the first known case of the store asserting a connection the code did not make — worse than an ordinary dead subsystem, because the document that is meant to be authoritative was the thing vouching for it. The wiring described above now exists; this paragraph stays so the correction is legible rather than silent.

The source of truth for the words themselves is PLANET_EMOTION_MAP in python/astrology/emotion.py: each planet carries a harmonious and a challenging palette, and aspect quality selects between them. This node was regenerated from that map on 2026-08-12, after the original was destroyed by the rollback incident recorded in the recovery commit.
