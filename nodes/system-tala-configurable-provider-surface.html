Semantic Memory

Tala's providers and endpoints are customizable runtime data. The application stores inference providers, search providers, git providers, storage providers, database providers, runtime instances, authentication credentials, and firewall contacts in PostgreSQL. Renderer settings panels call JSON-RPC methods to load, reorder, edit, and save these collections.

Inference providers include embedded, local, and remote model backends. Local endpoints can be auto-detected across common OpenAI-compatible local servers, including Ollama, LM Studio, vLLM, and generic local model servers. Endpoint normalization appends a versioned OpenAI-compatible path for local engines when users provide a bare host.

MCP is configurable through a persisted registry. Tala can register stdio MCP servers with command, args, cwd, and env config, or SSE MCP servers with URL, headers, and timeout config. The MCP manager redacts tokens, secrets, passwords, API keys, and authorization headers when listing configs. Tools are listed and called through the real MCP Python SDK when installed.

Auth credentials are a first-class provider surface. Tala stores prioritized SSH, RDP, API key, and OAuth-style credential records. Firewall contacts are also database-backed and describe trusted peer addresses and access rights. These records support local-first operation while allowing explicit remote, peer, and gateway integrations.

Settings saves update their corresponding private HTML-NN settings nodes. This means provider configuration is not only stored in database tables; it is mirrored into parseable private node memory so Tala can summarize and reason about its current configuration without relying on stale hardcoded assumptions.

Provider Tables

  • inference_providers: model backend type, name, priority, status, locked flag, and JSON config.
  • search_providers: search endpoint, API key, and priority, with fallback to direct DuckDuckGo HTML crawling.
  • git_providers: git host endpoint, username, API key, and priority.
  • storage_providers: heterogeneous storage credentials keyed by provider type.
  • database_providers: external or replica database endpoint, username, password, database name, and priority.
  • runtime_instances: remote HTML-NN runtime URLs, API keys, and priority.
  • auth_credentials: prioritized SSH, RDP, API key, and OAuth credential config.
  • firewall_contacts: cryptographic peer/contact identifiers and access-rights JSON.

MCP Contract

Registered MCP servers are opened on demand for each operation. A stdio server requires a command and can include args, cwd, and env. An SSE server requires a URL and can include headers and timeout settings. Tala stores server definitions in a user-data JSON registry and redacts sensitive fields when listing them.

{
  "name": "filesystem",
  "config": {
    "transport": "stdio",
    "command": "npx",
    "args": ["-y", "@modelcontextprotocol/server-filesystem", "."],
    "cwd": "D:/src/TalaV2"
  },
  "persist": true
}

Gateway Boundary

Plugins and MCP servers are untrusted surfaces. Plugin manifests declare identity, entrypoint, permissions, tools, MCP servers, and trust level. Gateway permission checks enforce declared access before plugin-registered tools run. Promptware defense scans and redacts tool output before it reaches the agent context.

This node is documentation only. It does not authorize connecting a provider, storing credentials, calling MCP tools, invoking shell commands, or changing gateway policy.
