Tool: run_tool_script

<p><strong>run_tool_script</strong> is a callable tool in Tala's registry. Execute a Python script that can call registered tools directly via `await call_tool(name, **kwargs)`. Collapses multi-step tool pipelines into one execution. The script's stdout and return value are captured.</p><p>Call it as <code>run_tool_script(code*, timeout_seconds)</code>, where <code>*</code> marks a required argument:</p><ul><li><code>code</code> (string, required)</li><li><code>timeout_seconds</code> (number, optional)</li></ul><p>The script body runs inside an async function with these names in scope: call_tool(tool_name, **kwargs) — await a registered tool list_tools() — names of every registered tool json — the json module Use `print()` for progress output and `return` for a final value. IMPORTANT: call_tool returns an ENVELOPE, not the tool's bare return value. The shape is: {"success": bool, "output": <the tool's actual result>, "risk_level": str, "error": str | None} So read the real payload from ["output"]. Scripts that treat the envelope as the result fail with confusing AttributeErrors. The tool name is positional-only, so tools taking a `name` argument (schedule_goal, delete_scheduled_goal, ...) work normally. Example: env = await call_tool("schedule_goal", name="nightly", cron_expr="0 9 * * *", goal_text="say hello") print(env["success"], env["output"]) env = await call_tool("list_scheduled_goals") jobs = env["output"].get("jobs", []) return len(jobs)</p><p>Implemented in <code>sdk.agent.tools</code>. The Python registry remains what actually executes; this node is the catalogue entry that makes the tool retrievable and referenceable from a workflow.</p>
