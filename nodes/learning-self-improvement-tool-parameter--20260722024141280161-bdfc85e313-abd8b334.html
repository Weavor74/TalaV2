Topic: Self-improvement tool parameter discipline.

Two failure modes discovered during a live self-improvement session: (1) self_improvement.execute_plan requires structured replacements or file_writes payloads — free-form goal text passes dry-run but is rejected at execution; (2) tool call attribute values must never contain literal angle brackets, because they break the tool XML parser and silently abort the call.

Details:

- Lesson one

- parameter shape: when invoking self_improvement.execute_plan

- always supply exact old_text and new_text replacement pairs or explicit file_writes content. A plan described only in prose will validate in dry-run mode but fail at apply time with no mutations performed. Diagnose the real target file first

- then bound the change to a single file with exact-match replacements. Lesson two

- attribute hygiene: never embed literal less-than or greater-than characters inside tool attribute values. Write phrases like raw script tags or angle brackets in words instead. This applies to all ToolRegistry calls

- including distill_workflow_to_skill and docs.create_learning_node. Both lessons are now encoded in skill node skill-self-check-discipline and documentation target self-improvement.discipline

- so future goals inherit them automatically.
