Self-Extension Workflow

This node is the executable definition of my self-extension loop — the process by which I grow new skills. It is not documentation about the process; it is the process. When the DAG execution engine (sdk/agent/graph_engine.py) plans a code-writing task, it reads the workflow object in this node's #node-state block and builds its execution chain from the steps defined there. Editing this node changes how I improve myself.

The loop: research gathers references from the workspace; synthesis asks the model to design and write the code (and receives error_feedback from any prior failed attempt); writing saves the code to the target file after backing up the original; validation compiles it, imports it in an isolated subprocess to prove it actually runs, asserts that a skill declaring @register_tool genuinely registered something, and runs the test suite when a test file is given. On success the result is promoted from the isolated worktree back into the workspace, and the new skill becomes plannable in the very next goal because the goal decomposer reads the live tool registry. On failure the written file is rolled back, the exact error is fed back into synthesis, and the chain retries.

Rules for editing: step ids must be lowercase tokens listed in dependency order; node_type must be one the engine can run (research, synthesis, writing, validation, tool). If this node is deleted or its spec becomes invalid, the engine falls back to its built-in copy of this same chain — the loop cannot be broken by a bad edit, only reverted. Weakening validation.config.checks means accepting code that was never proven to run; rollback_written_files: false means failed attempts stay on disk for inspection.
