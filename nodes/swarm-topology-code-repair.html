Swarm Topology: Code Repair Swarm

This node is the executable definition of the 'Code Repair Swarm' swarm. It is not documentation about the swarm; it is the swarm. When a run is started with topology_id 'swarm-code-repair', SwarmEngine reads the 'topology' object in this node's #node-state block and builds the run from the nodes, edges and failure policy defined there. Editing this node changes how that swarm behaves on its next run.

Roles in this swarm: planner (planner) — Plan the fix; coder (coder) — Implement the fix; tester (verifier) — Run the tests; reviewer (reviewer) — Review the code; documenter (documenter) — Document the changes.

Flow: starts at planner. Every edge carries a gate: planner -> coder requires 'success'; coder -> tester requires 'success'; tester -> reviewer requires 'tests_passed'; reviewer -> documenter requires 'approved'.

Rules for editing: node ids must be lowercase tokens and unique; every edge must reference nodes defined in this same spec; the edge graph must stay acyclic (backward movement is expressed with failure_policy.route_to, which is bounded by max_retries, not with an edge); and every edge condition must name a rule GatedVerifier actually implements, otherwise that branch could never advance. If this node is deleted or its spec fails validation, the registry keeps the last valid definition of this topology_id and logs why the edit was rejected.
